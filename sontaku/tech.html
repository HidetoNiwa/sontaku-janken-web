技術の説明

勝負に戻る

カメラの映像はブラウザの中だけで処理します。サーバーへは送りません。

全体の流れ

勝負のあいだ、次の順で手が決まります。どれもこの端末のブラウザの中で完結します。

  1. カメラ映像
  2. 関節21点
  3. 形3種
  4. 確定連続
  5. 負け手相手の勝ち

画面の構成

フレームワークは使っていません。HTML、CSS、JavaScript だけです。判定のルールは画面の処理から分けてあり、ブラウザがなくてもテストできます。

ページをファイルとして直接開くと、カメラとモジュールが使えないブラウザがあります。公開サイトは静的なファイルを渡すだけで、映像は受け取りません。

カメラ

ブラウザの getUserMedia で、内側のカメラを使います。映像は画面の外にある video 要素で再生し、認識へ渡します。見えている絵は canvas に描き直したもので、左右を反転しています。自分の右手が右側に見える、鏡と同じ向きです。関節を結ぶ線も、同じ反転の中で描きます。

カメラが複数あるときは、一覧から選べます。

手の関節を読む

手の位置は、Google の MediaPipe Tasks Vision にある Hand Landmarker が推定します。学習済みモデルは軽量な float16 版で、このサイト自身から配信します。計算本体は WebAssembly です。まず GPU で動かし、失敗したときだけ CPU に切り替えます。

検出するのは手ひとつです。返ってくるのは、手首から各指の先まで 21 個の点です。点が少しでも揺れると形がちらつくので、検出の信頼度は 0.6 を下回るものを捨てています。

グー・チョキ・パーの見分け

親指は判定に使いません。人差し指、中指、薬指、小指の4本だけを見ます。指が伸びているかは、画像の上の距離で決めます。

  • 指先が、第二関節よりも手首から十分遠いか
  • 指先から付け根までの長さが、曲がった指より長いか

その結果を、次のルールで一つの形にします。

見えている指判定
人差し指と中指だけが伸びているチョキ
人差し指、中指、薬指が伸びているパー
4本とも曲がっているグー
どれにも当てはまらない読まない

中途半端な形は、意図的に捨てます。あいまいなまま手を出すと、読み違いでこちらが勝ってしまうためです。

いつの手で勝負するか

映像のフレームごとに形を覚え、直近おおよそ 280 ミリ秒だけを見ます。そのうち最新の5回中4回が同じ形なら、その形で確定します。1フレームだけ別の形に見えても、手は変わりません。

正式の掛け声は「最初はグー、じゃんけん、ぽん」です。画面の切り替えと、音の高さが合図になります。日本語の読み上げは Web Speech API、音程と「ぽん」の拍手は Web Audio API です。読み上げができなくても、画面と音程で合図は残ります。

「最初はグー」では、グーが認識できるまで次へ進みません。グーが出ていなければ、出すよう画面で促して待ちます。グーを確認してから「じゃんけんぽん」に移ります。「じゃんけんぽん」だけの早掛けでは、この確認はありません。

手は「ぽん」の瞬間に出されることがあります。そのため、ぽんの音が鳴った時点の形では勝負しません。音と同時に、それまでの読みは捨てます。音から 0.2 秒たって、そのあいだに見えた形が安定していれば、そこで負け手を出します。まだ形が定まっていなければ、安定するまで見ますが、音から 0.75 秒を過ぎても読めなければ手は出さず、「読み取れず」と記録します。

記録の内部では、勝敗はこちらの側で持っています。こちらが負けた回は、画面では「あなたの勝ち」です。忖度成功率は、読み取れた勝負のうち、こちらが正しく負けた割合です。「読み取れず」は、この割合には入れません。

記録とグラフ

結果はブラウザの localStorage に残し、最大 200 件です。グラフは Chart.js 4 です。折れ線はあなたの勝ち数の累計、棒グラフは勝ち・負け・あいこ・読み取れず、ドーナツは相手が出した手の内訳です。CSV は Excel で文字化けしにくいよう、先頭に BOM を付けて書き出します。

テストしていること

js/logic.mjs の判定は、画面やカメラがなくても確認できます。Node.js のテストランナーで、次を見ています。

  • どの手に対しても、出す手が必ず負けになる
  • グー、チョキ、パーを見分け、あいまいな形は捨てる
  • 同じ形が続くまで確定しない
  • 勝ち数の累計と、連勝が途切れる条件
  • 壊れた記録を捨て、200件を超えた分を残さない
